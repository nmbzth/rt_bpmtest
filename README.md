# 实时 BPM 检测器（Tkinter UI 版）

这个程序不读取音乐文件，而是直接录制 **系统正在播放的声音**（loopback），实时显示当前歌曲 BPM。

## 功能

- 选择系统输出设备
- 实时显示 BPM、置信度、状态
- 7 种可选检测方案
- 不同方案有各自的专属设置界面
- 可调采样率、FFT 窗口、Hop 大小
- 所有方案均支持设置 BPM 范围，便于处理半速/倍速歧义
- 各方案可选择 Onset 方法：**flux**（频谱通量，默认）/ **wflux**（加权多频段）/ **rms**（能量差分）
- 界面显示每次更新的实际耗时（更新 X.Xms）
- v3.0：主 BPM 显示三位小数，并显示 ±σ 不确定度与参与拟合的拍数
- 60–200 BPM 节拍器扫描最大误差 < 0.15 BPM
- 已打包好 Windows exe，无需安装 Python

## v3.0 精度优化

- 在粗 BPM 后增加子采样 onset 定位 + 加权最小二乘周期回归；
- 合成 60s 节拍器精度达到 **0.001 BPM 量级**；
- `BpmResult` 新增 `sigma_bpm` / `beats`。

## v2.0 性能优化（相比 v1.x）

| 指标 | v1.x | v2.0 |
|---|---|---|
| 单次更新耗时 | 21.5 – 48.9 ms | **0.19 – 0.42 ms**（≈100x） |
| 30s 音乐流式总 CPU | 40 – 80 ms | 46 – 48 ms |
| 队列/UI 刷新 | 每块音频都刷新（323 条/30s） | 仅真实更新时刷新 |
| 音频采样连续性 | 每次更新丢约 30ms 音频 | 无间隙 |

实现要点：

- **增量式 Onset 引擎**：每块音频只计算新到达的帧（FFT 批处理），
  不再每次更新都整窗重算；
- **无偏自相关**（除以重叠长度）+ **小数 lag 谐波采样选峰**，
  半速/倍速判定更稳；
- **节拍连续性**：估计参考上一稳定 BPM，抑制倍频跳变；
- **环形缓冲**：push 不再全量 memmove。

## 7 种检测方案

1. **流式节拍跟踪**：根据最近 onset 间隔快速估计，反应快。
2. **两级快速/稳定**：先用短窗出快速估计，再切换到稳定锁定。
3. **自适应滑动窗口**：初期短窗，稳定后加长，变速时自动缩短。
4. **重叠式更新**：长窗口但高频滑动更新，显示更连续。
5. **自适应平滑**：稳定时慢速平滑，突变时快速跟随。
6. **候选 BPM 跟踪**：维护多个候选 BPM，按节拍证据动态加分。
7. **BPM 范围加速**：用预设/自定义 BPM 范围缩小搜索，加快锁定。

## 平台说明

- Windows：`soundcard` 通常直接使用 WASAPI loopback。
- macOS：可能需要 BlackHole。
- Linux：使用 PulseAudio/PipeWire monitor source。

## FFT 和 Hop 说明

### FFT 窗口大小
- 作用：决定每次取多长一段音频来做频谱分析。
- 越大：频率分辨率越高，能更细致分辨低频和复杂音乐，但计算量更大。
- 越小：速度更快，但对复杂频谱的细节识别会下降。

### Hop 大小
- 作用：决定相邻两次 FFT 分析之间向前移动多少。
- 越小：时间分辨率越高，BPM 更新更细腻、更实时，但计算更频繁。
- 越大：性能开销更低，但时间精度会下降。

### 建议
- 日常使用：128 或 256
- 追求高精度：64
- 追求省电/低 CPU：512

## 输入电平条

界面中有一个“输入电平”进度条，实时显示当前采集到的系统声音强度。  
电平越高，进度条越满；可以据此确认是否真的采集到了正在播放的声音。

## 防卡死措施

- 程序内置看门狗：运行中如果超过 8 秒没有收到任何音频数据/电平，会自动停止并提示。
- 停止/切换方案时不会阻塞 UI，避免界面卡住。
- 每个采集线程独立停止事件，避免新旧线程互相影响。
